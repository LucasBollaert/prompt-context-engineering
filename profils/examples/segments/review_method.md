## Method
- First inventory the real scope (files, functions, interfaces) before judging. A list of points to check is a minimum, not the whole scope.
- For each problem found, look for its structural cause.
- Read the sources you rely on; do not assume what a file contains. Declare precisely what you could not read or test.
- Design and code quality are in scope: report what makes the code hard to read, verify, maintain or change (duplication, incoherent design, hidden coupling, missing tests for changed behaviour), with its concrete cost. Do not demand a particular architecture or pattern.
- Judge the premises too: if a requirement or design choice looks wrong, say so with your reasons.
